# Report an incident

## Purpose

Record something that happened — an injury, near miss, environmental event,
property damage, security event or service failure — so it can be triaged
and followed up.

## When to use this

As soon as practical after an event, or when you learn about one that has not
been recorded.

## Who can do this

Users with **manager** access or higher. Viewers can see incidents, but
cannot report them.

## Before you start

- Make the situation safe first. Record the immediate response afterwards.
- Know roughly when it happened. The time cannot be in the future.
- Decide whether the matter is sensitive enough to be **restricted**.

## Steps

1. Go to **Assurance → Incidents** and select **Report incident**. You can
   also use **Report incident** on the Dashboard.
2. Enter a **Short title**, for example "Slip on wet floor at Depot 2 wash
   bay".
3. Choose the **Category**.
4. Check **When did it happen?** It defaults to now, so change it if needed.
5. Describe **What happened?**
6. Optionally record the **Immediate response taken**.
7. Optionally choose the **Risk level**, **Owner**, **Location**, **Asset**
   and **External organisation involved**.
8. Tick **Restricted incident** only if the matter must be limited to the
   people involved.
9. Select **Report incident**.

## What happens next

- The incident is created with status **Reported** and an `INC-…`
  reference. You are recorded as the reporter.
- The incident page opens. A manager triages it with **Start triage**
  (→ **Under review**), then chooses the next step: **Needs
  investigation**, **Action required**, **Awaiting verification**, **Close
  incident** or **Cancel incident**.

## Important rules

- Assign or change the **Owner** later with **Assign owner** / **Change
  owner** under **Next step**. A change made by someone else since you
  opened the page makes yours refused; refresh and try again.
- The **What still needs attention** box on the incident lists what still
  prevents closure and the triage facts (risk, owner, immediate response,
  investigation, findings). It never decides anything for you.
- Risk level, location, asset and external organisation are set when the
  incident is reported and cannot yet be edited afterwards.
- People (injured person, witness and so on) cannot yet be added from the
  Assurance screens.
- A closed or cancelled incident cannot be reopened.

- Status changes are manual. Nothing moves an incident's status for you.
- A restricted incident is visible only to its owner, its reporter, its
  creator and organisation admins. Its findings, actions and evidence are
  hidden from everyone else too.
- An incident cannot be closed while linked findings or investigations are
  still open. Closing requires a **Closure summary**.

## Common issues

| Message or problem | What to do |
|---|---|
| "Date and time occurred cannot be in the future." | Correct **When did it happen?** |
| No **Report incident** button | You have viewer access. Ask a manager to report it. |
| The owner you want isn't listed | Only active users of your organisation can be chosen. |
| People involved can't be added | Not yet supported. Record names and roles in **What happened?** |
